# 自动语义推断阈值

「BIM翻模大师」在没有项目级图层规则表时使用的判据。与代码 `RevitModeler.Core/LayerSemantics.cs` 保持一致。

## 图层名关键词（命中即高置信）

| 类别 | 中文关键词 | 英文关键词 | 置信度 |
|---|---|---|---|
| 柱 | 柱 | column | 0.92 |
| 门 | 门 | door | 0.90 |
| 窗 | 窗 | window | 0.90 |
| 墙 | 墙 | wall | 0.90 |
| 楼板 | 楼板 | floor / slab | 0.88~0.92 |
| 地面/天花 | 地面 / 天花 | finish / ceiling | 0.80 |
| 家具 | 家具 / 家俱 | furniture | 0.90 |
| 标注 | 标注 / 文字 / 轴线 | dim / text / axis | 0.85~0.95 |

## 几何特征推断

| 特征 | 推断 | 置信度 |
|---|---|---|
| 闭合多段线，面积 ≥1㎡ | 楼板 | 0.72 |
| 闭合多段线，面积 <1㎡ | 楼板（待复核）| 0.55 |
| 线段 ≥600mm + 平行近邻（20~400mm）| 墙（双线墙）| 0.72 |
| 线段 ≥600mm，无平行近邻 | 墙占位（待复核）| 0.45 |
| 圆弧 | 门开启线（待复核）| 0.45 |
| 圆 | 柱（待复核）| 0.40 |
| 块名含关键词 | 对应族类 | 0.55~0.75 |

## 处理分档

- ≥0.7 高置信：直接建模
- 0.4~0.7 中置信：先占位建模，标记待图像复核
- <0.4 低置信：不建模，列入问题清单

## 全套施工图：图纸分类与构件尺寸识别

多图并置的全套施工图必须先分区再识别，完整流程见 `SKILL.md` 〇-A。要点如下。

### 图层 → 构件（含排除项）
| 构件 | 命中图层 | 关键排除 |
|---|---|---|
| 墙 | WALL / 墙 | WINDOW/窗、STAIR/梯、DIM/标注 |
| 柱 | COLUMN / 柱 | — |
| 板 | FLOOR / SLAB / 楼板 / ROOF / 屋面板 | 「踢脚板」「栏板」等误匹配 |
| 窗 | WINDOW / 窗 | 并入墙会导致墙数虚高 |
| 楼梯 | STAIR / 梯 | 全部排除 |
| 标注/轴线/文字/图框/填充 | DIM/AXIS/TEXT/TITLE/HATCH | 全部排除 |

### 尺寸判据
| 构件 | 几何判据 | 吸附 / 容差 |
|---|---|---|
| 墙 | 双线间距 或 闭合轮廓 min(bbox) | 标准 60/80/100/120/150/180/200/240/280/300，±25mm；超出判非墙 |
| 柱 | **块引用 ScaleX/Y（单位块=截面）** > 闭合矩形 bbox 300~2000 | 不吸附，取实测 |
| 板 | 闭合轮廓 + 「板厚N」文字（正则） | 无依据默认 120 并标 `inferred` |
| 梁 | 梁图层 / 集中标注 b×h | 无依据 → 墙中线 + 默认 300×700，标 `default` |

### 两个关键坑（实测踩过）
1. **整张图在块里**：模型空间只剩图框时，先看块定义规模。>200 图元的块 `Explode()` 展开，并以顶层块名作为 `sheet` 分区键；否则会得出"图纸是空的"的错误结论。
2. **柱不是矩形而是块缩放**：`COLUMN` 图层 535 个图元全是 `_FZH` 单位块引用（1×1 Solid），截面只在 `ScaleX/Y` 里。查截面不要去量 bbox，直接读缩放。

### 实测校验（某宾馆全套施工图）
- 修复前：304 面墙，其中 198 面来自 `S_E_STAIR`（楼梯），墙厚 300 占 211 → 严重误建。
- 中间版：53 面墙（来自 `S_WALL`，但那是一张剖面/详图，不是平面）。
- 最终版（块展开+图纸分区，选三层平面图）：149 面墙（240×114、120×33、150×2）、50 根柱（600×600×34、700×700×16）、104 段梁（默认 300×700）、板厚 100mm（图面「板厚100」）。
- 实测精度：四类构件 100% 还原，端点/截面/厚度误差 0.00mm（残差 1e-11mm 量级）。
- 结论：柱截面与板厚可从图纸确定性识别；梁无图层无标注，只能默认并标记。

## Revit 写入侧的两个必踩坑

尺寸从图纸识别对了，还要能写进 Revit 才算数。这两处都曾让"识别正确、模型错误"。

### 坑 1：基本墙的宽度参数永远是只读的

`BuiltInParameter.WALL_ATTR_WIDTH_PARAM` 对基本墙恒为只读——它的值由复合结构
（`CompoundStructure`）反推而来。用「参数可写」当可用性判据，会把所有基本墙类型判死
（曾出现 125 面墙全部跳过）。正确做法：改 `CompoundStructure` 的层厚再 `SetCompoundStructure`，
写入后回读校验；容差收紧到 1mm（6mm 容差会让 120 墙建成 124mm）。

### 坑 2：楼板基准类型不能按「厚度最接近」挑

`OrderBy(|厚度 − 目标|).First()` 看着合理，实际会在样板里挑到
**「75mm 金属屋顶板」**——它的压型层宽度由轮廓形状决定，`SetLayerWidth` 直接抛
`ArgumentException: The width of the layer is not valid`，于是整块板建不出来。

按三层修：

1. **选型**：通用类型优先（名含「常规/Generic」）→ 无变截面层 → 层数少 → 厚度接近，
   然后**逐个尝试**，命中即用，不要赌第一个。
2. **兜底**：缩放失败就 `CompoundStructure.CreateSingleLayerCompoundStructure(...)`
   整体替换为单层结构（沿用原结构层材质）。翻模验收指标是总厚度，构造配比无意义。
   **端部条件必须从原复合结构继承**（`single.EndCap = cs0.EndCap`）——默认构造出来的 EndCap
   与楼板类型不匹配，`SetCompoundStructure` 会报
   `Input compound structure has wrong EndCap condition for this element type`。
   这个坑在正常流程里暴露不出来（主路径走缩放就成功了），必须单独探针验证。
3. **可观测**：失败原因（层数、异常消息）必须拼进 warning，不能 `catch { return false; }` 吞掉——
   这次就是因为吞了异常，日志只显示「复合结构替换失败」，查了很久才发现是类型选错。

> 验证手段：`fanmo_diagnose` 支持 `probeFloorType` / `probeThicknessMm`，复制一份类型分别走
> 「层缩放」「单层重建」，回读厚度后删除副本（事务内，不改文档）。
> 实测：75mm 金属屋顶板 缩放❌/单层✅；常规-300mm 双✅；混凝土-民用 425mm(多层) 缩放❌/单层✅。

> 配套要求：失败的类型复制要立刻 `Delete`，同名类型已存在时**修正它**而不是加随机后缀新建，
> 否则多轮翻模会让文档里的 `BIMOne_Floor_*` 无限膨胀（实测第二轮就会翻倍）。

## Revit 显示侧的三个必踩坑（「模型建好了但屏幕上空的」）

墙 149/149 都在文档里、几何实心、bbox 正常、无隐藏无过滤——屏幕上却什么都没有。
这三个坑任何一个都能造成这种"全绿但空白"，且互相叠加。

### 坑 1：视图规程=结构时，非承重建筑墙不绘制

实测（Revit 2025）：规程「结构」的视图（平面/三维一样）不画 `structuralUsage=非承重` 的建筑墙——
bbox-in-view 非空、`GetCategoryHidden=false`、阶段匹配、导出图**照样空白**。新建三维视图还会继承
样板的「结构」规程。修复：定位模型时把规程切到「协调」（`VIEW_DISCIPLINE` 设 5）。
判定线索：**线（标高/模型线）画得出来、墙画不出来** = 规程或类别级压制，先查规程。

### 坑 2：`ViewOrientation3D` 的 forward/up 存储顺序与文档签名相反

文档签名是 `(eye, forward, up)`，但按文档传参后 `GetOrientation().ForwardDirection` 返回的是
**传入的 up**（探针读回逐位吻合）。相机因此朝天上方向看，屏幕全空。修复：交换传参
`new ViewOrientation3D(eye, up, forward)`，并用 `fanmo_diagnose` 的 orientation 读回验证。

### 坑 3：`FilteredElementCollector(doc, viewId)` 不可信

部分上下文里它只返回符号类元素（立面标记/相机），连标高都不返回——149 面墙、149 个
bbox-in-view 非空，它却返回 0。**判定"视图能否显示模型"必须用 `get_BoundingBox(view) is not null`**，
不能用它做可见性判断（会误判"视图不收录模型"而反复新建视图）。

> 配套验证手段：`fanmo_snapshot`（`fitModel` 按模型 bbox 临时开裁剪导出）导出的图不受
> 屏幕重绘/模态框影响，是唯一可信的"用户能不能看见"判据；`fanmo_diagnose` 的
> `setDiscipline` 探针可实测规程显示规则。教训：**模态警告框挂着时屏幕不重绘**，但导出
> 不受影响——屏幕空而导出有内容是弹窗问题，两者都空才是显示问题。
