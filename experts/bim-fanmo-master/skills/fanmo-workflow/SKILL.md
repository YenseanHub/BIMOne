# CAD→Revit 翻模工作流

本 skill 固化「BIM翻模大师」的执行细节。主流程见 `SKILL.md` 的 Phase 0~5，这里提供**判据、阈值、输出模板**。

## 〇、文件交接协议（CAD 端与 Revit 端唯一耦合点）

两端**不共享进程、不直接通信**，只通过本地 JSON 文件交接（详见 `BIMOne/DATA-LAYER.md`）：

```
work/<task>.ir.json          ← cad__parse_cad(path, outPath=...)
work/<task>.verify.json      ← cad__verify_image(path, outPath=...)
work/<task>.commands.json    ← 你研判后写出（核心产物，可直接 Read/Edit）
work/<task>.review.json      ← revit__fanmo_review(outPath=...) 回写
```

- Phase 1 落盘 IR 后 `Read` 它做研判；Phase 4 写出 commands.json；Phase 5 把它作为 `revit__fanmo_build(dataPath=...)` 的输入。
- **commands.json 是唯一交接产物**：改研判结果只改这个文件，不必重跑 CAD、不必动 Revit。
- 每项坐标必须来自 IR 真实 `start/end/points`；`category` 用 `Wall`/`Floor`/`Door` 等英文（与 C# `FanmoElement` 对齐）。

## 〇-A、图纸分类与构件尺寸识别（全套施工图必读）

真实项目常把建筑平立剖、结构、水暖电、总图、大样放在同一个 DWG（多图并置），坐标可散布数十万 mm。**禁止整体翻模**，先分类再识别。

### 1) 图纸分区（先展开块，再聚类）
- **先展开块**：天正/结构软件常把整张平面图塞进一个块定义，模型空间只剩图框。判据：**块定义图元数 > 200 → 视为"整张图纸"并展开**（解析层已自动做，IR 里以 `sheet`/`sheetTitle` 标注；实测某宾馆 DWG 从 9197 图元展开到 42478 图元、32 张图纸）。小块（门/窗/柱，如 `_FZH`）保持 Insert 不展开，保留块名与缩放语义。
- 用结构图层（COLUMN/WALL/FLOOR）图元坐标聚类成若干「图框簇」。
- 取墙/柱/轴线图元最多的簇为**主平面图**；总图（STREET/GROUND）、大样（WALL1 窄条）、水暖电（WS_）单独成簇，不参与结构翻模。
- 按标题文字定层：`一层平面图/四--十三层平面图/屋顶平面图/…大样`，据此选目标层并推层高（图面标高文字 3.900/7.500/…）。
- 判据：同簇 x/y 跨度 < 50000mm；跨簇间隔 > 5000mm。

### 2) 图层语义分类（命中即高置信）
| 类别 | 图层关键词 | 处置 |
|---|---|---|
| 墙 | WALL/墙（排除 WINDOW/窗、STAIR/梯、DIM） | 主结构墙，建 |
| 柱 | COLUMN/柱 | 注意常为柱立面/配筋，非平面截面 |
| 板 | FLOOR/SLAB/楼板/ROOF/屋面板 | 建板 |
| 窗 | WINDOW/窗 | 单独处理，勿并入墙 |
| 楼梯 | STAIR/梯、轴线、标注、文字、图框、填充 | 排除，勿建墙 |

**有明确墙图层时只用墙图层；图层名全为 0/数字时才退回全图几何兜底。** 这一步能把楼梯线、总图线、柱线误建墙的情况清零（实测：某宾馆图误建从 304 面降到 53 面）。

### 3) 构件尺寸识别优先级（实测有效路径）
- **墙厚**：①闭合轮廓宽度（min bbox）②双线间距；吸附到标准值（**含 280 剪力墙**），偏差 >25mm 判为非墙。
- **柱截面**：**首选柱图层的块引用缩放**——天正/结构软件常把柱做成"单位块"（如 `_FZH` 是 1×1 的正方形），Insert 的 `ScaleX/Y` 就是截面 b×h（实测 600/700/820/1200/1400mm，可直接落库）；其次闭合矩形 bbox（300~1200mm）；柱图层只有立面线（高 3000/3900 的竖线）时**不得臆造截面**。
- **板厚**：优先正则扫图面文字 `板厚\s*[:：]?\s*(\d{2,3})`（同一图纸多处一致即采信，本图=100mm）；无标注用项目默认 120mm 并标记 `inferred`。
- **梁截面**：需独立梁图层（BEAM/梁）或集中标注（KL/LL + b×h）；全图无梁信息时按**墙中线 + 默认截面**生成，`source` 标记 `default:wall-centerline`，并在报告注明"位置与截面均为推断"。

### 4) 构件可识别性矩阵（随报告输出）
| 构件 | 自动识别条件 | 缺失时处置 |
|---|---|---|
| 墙 | 墙图层双线/闭合轮廓 | 几何兜底 + 图像复核 |
| 柱 | 柱图层块引用缩放 / 闭合矩形 | 有则建、无则跳过（不臆造） |
| 板 | 板图层闭合轮廓 + 「板厚N」文字 | 默认 120mm + 标记 inferred |
| 梁 | 梁图层/集中标注 | 墙中线 + 默认 300×700 + 标记 default |

### 5) 精度验收线（每轮翻模必须给数）
- 墙：端点误差 ≤1mm、墙厚误差 ≤5mm、双线支撑率 100%
- 柱：定位误差 ≤1mm、截面误差 ≤5mm（目标值来自块缩放，属确定性数据）
- 梁：端点误差 ≤1mm、截面误差 ≤5mm（默认截面时只验证落库一致性）
- 板：厚度误差 ≤1mm、轮廓边界误差 ≤1mm

## 一、语义推断判据（无项目规则时）

优先级从高到低，命中即停：

1. **图层名关键词**（高置信 0.88~0.95）
   墙/WALL、门/DOOR、窗/WINDOW、柱/COLUMN、楼板/FLOOR/SLAB、标注/DIM/TEXT、家具/家俱/FURNITURE、天花/CEILING、地面/FINISH。
2. **文字图元**（0.95）→ 标注，Skip。
3. **块名含关键词**（0.55~0.75）→ 对应族类，LOD200 时用。
4. **几何特征**
   - 闭合多段线且面积 ≥1㎡ → 楼板（0.72）；<1㎡ → 楼板（0.55，待复核）
   - 线段长 ≥600mm 且有平行近邻（间距 20~400mm）→ 墙（0.72，双线墙）
   - 线段长 ≥600mm 无平行近邻 → 墙占位（0.45，**必须图像复核**）
   - 圆弧 → 门开启线（0.45，待复核）
   - 圆 → 柱（0.40，待复核）

置信度分档：≥0.7 直接建模｜0.4~0.7 占位+标记待复核｜<0.4 跳过并列问题清单。
阈值定义在 `RevitModeler.Core/LayerSemantics.cs`，可由专家在研判中调整但需记录理由。

## 二、图像交叉验证判读

- 工具：`cad__verify_image(path, irPath?, outPath?)`，图像源 = DWG 内嵌预览图（DwgReader.ReadPreview）。传 `outPath` 落盘报告供 Read。
- 关键字段：`globalIoU`、`previewCoverage`（预览线被解析覆盖比例）、`irPrecision`（解析线在预览有支撑比例）、`regions`（低一致网格）。
- **判读原则**：
  - `previewCoverage` 低 → 重点怀疑**漏解析**（图层被跳过、Z 值异常、类型不支持）。
  - `irPrecision` 低 → 重点怀疑**误判**（标注/家具被当成墙）。
  - 单格 IoU<0.15 且提示"预览有线解析缺失" → 定位该网格对应图纸坐标，检查该区域图元。
  - 预览图只含保存时可见图层、线宽 2~3px → 存在系统性偏差，**低 IoU 不等于错误**。
- **多轮收敛**：不一致 → 换证据/调阈值/问用户 → 重推断 → 再验证。两轮仍不一致 → 明确标记为"需人工确认"，不强行下结论。

## 三、常见坑与处置

| 现象 | 处置 |
|---|---|
| Z 值非零 | 平面翻模必须先 Z 归零，否则墙板飘空间 |
| Spline 占比高 | 样条拟合降级为多段线，不能直接成墙 |
| 图层名全是 0/3/数字 | 走几何特征推断 + 图像复核，不要套图层名规则 |
| 大量短线段 | 多为家具/标注细节，低置信跳过比误建成墙好 |
| 墙全堆原点 | 检查 IR 的 start/end/points 是否贯穿（CommandSerializer 会拒绝无坐标图元）|
| 编译通过但无模型 | 本机无 Revit 时属正常，ExternalEvent/Transaction 需实机验证 |
| 改一行命令就要重启 Revit | 命令集支持热更新，用 `deploy-hot.ps1`，见「三-A」 |

## 三-A、插件开发与热更新（工程侧）

改 Revit 端代码前先判断改的是哪一层，只有 Plugin 壳需要重启：

| 改动位置 | 生效方式 |
|---|---|
| `RevitModeler.Plugin`（Ribbon / socket / 加载器） | 必须重启 Revit 一次 |
| `RevitModeler.CommandSet` / `RevitModeler.Core` / `command.json` | `deploy-hot.ps1` 热重载，无需重启 |
| `RevitModeler.McpServer`（Node） | 重启该 Node 进程，与 Revit 无关 |

日常流程：

```powershell
powershell -ExecutionPolicy Bypass -File revit-modeler/scripts/deploy-hot.ps1            # 编译 + 覆盖 + 热重载
powershell -ExecutionPolicy Bypass -File revit-modeler/scripts/deploy-hot.ps1 -VerifyOnly # 只看当前加载状态
node work/hotel/verify-hotreload.mjs                                                      # 端到端验证链路
```

加载失败会原子回滚到上一版本，旧命令继续可用，不会把服务搞挂。完整原理、边界与排错表见 `references/dev-hot-reload.md`。

## 五、边界声明（必须随报告给出）

1. 交叉验证只能显著降低错漏，**不能保证 100%**，最终质量靠人工在 Revit 复核。
2. 无 Revit 2025 实机时，只能声明"编译通过/逻辑验证"，不能声称模型已生成。
3. 族库精化（LOD200）需要真实 .rfa 族文件；无族库时只做 LOD100 占位。
